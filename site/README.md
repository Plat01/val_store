# Магазин «собери станок»: этапы 0–7

## Запуск

Из корня проекта:

```sh
npm ci
npx playwright install chromium
npx @playwright/mcp install-browser chrome-for-testing
cd site
cp -n .env.example .env
./scripts/bootstrap.sh
./scripts/import-old.sh ../old_site/public_html/wp-content/backups-dup-lite/20200602_chpumaster_0a172198a54a8a077690_20200602082120_database.sql
./scripts/verify.sh
```

Сайт: http://localhost:8080/catalog/; админка: http://localhost:8080/wp-admin/.
Локальная учётная запись из `.env`: `admin` / `admin`.
Письма: http://localhost:8025. Настройки → Данные магазина: контакты,
реквизиты, адрес самовывоза и список получателей уведомлений.

Только бесплатные плагины. Redis Object Cache подключается на серверном этапе.
Rank Math работает без облачного аккаунта: штатный пропуск регистрации записан
в настройку. Индексация закрыта (`blog_public=0`). Оплата при получении,
самовывоз, RUB, кг/см, Россия, часовой пояс магазина — Москва.

## Импорт

`./scripts/import-old.sh` повторно импортирует уже загруженную БД `old`.
Дамп передаётся необязательным аргументом (`.sql` / `.sql.gz`). Перед загрузкой
проверяется доступность файла. Перезаписывается только временная БД `OLD_DB`.
Старый сайт смонтирован только для чтения; его тема, плагины, страницы, меню,
заказы и покупатели не переносятся.

Сопоставление по `_ss_old_id` обеспечивает обновление товаров, вариаций,
категорий и повторное использование изображений. Товары с модерацией становятся
черновиками. Исчезнувшие товары перемещаются в корзину, исчезнувшие вариации
удаляются. Сохраняются все категории, в том числе пустые, и их иерархия.
WPBakery/WoodMart удаляются из описаний, локальные характеристики без вариаций
переводятся в глобальные атрибуты для будущих фильтров. Вариационные ключи
сохраняются с транслитерацией Cyr-To-Lat.

Новые адреса: `/catalog/<категория>/<подкатегория>/<товар>/` и
`/catalog/<категория>/<подкатегория>/`. Основная категория перенесена из Yoast
в Rank Math. Старые пути без `/catalog/` перенаправляются одним 301 через
Rank Math; записи обновляются по сохранённым ID. Карта: `data/url-map.csv`
(столбцы `path`, `old_path`).

В дампе 2020: 123 опубликованных товара, 2 черновика, 283 вариации, 35 категорий.
Импортировано 162 файла изображений (173 использования в карточках; изображения
в описаниях/категориях учитываются отдельно). Исходник `sfu.png` отсутствует:
найдены только миниатюры 10×10 и 10×14, их не используем вместо оригинала.
Импорт сообщает предупреждение и сохраняет остальные доступные изображения.

## Проверки

```sh
# Из site:
./scripts/verify.sh
# Из корня:
npm test
npm run check:mcp
```

`verify.sh` сверяет товары/вариации, статусы, слаги, цены, артикулы, размеры, остатки, иерархию
категорий, отсутствие дублей и доступность импортированных файлов.
Playwright проверяет всю карту URL, 301 без цепочек, гостевой заказ с оплатой
при получении и самовывозом, уведомление в Mailpit и выбор вариации; снимает каталог, товар и
корзину в 375/768/1440 px. Скриншоты: `data/screenshots/`.
Тест создаёт локальный заказ для `playwright-…@example.test`.

Lighthouse установлен и запускается командой `npm run lighthouse -- URL`.
Результаты готовой темы и SEO-фундамента приведены в разделах этапов 5 и 6 ниже.

## Этап 5: тема и страницы

Вариант A работает на [главной](http://localhost:8080/) и в магазине.
FSE-шаблоны: главная, каталог, категория/метка, товар, корзина, оформление,
поиск, 404, обычная страница. Шапка и подвал — части темы; секции вставляются
через 6 паттернов «Собери станок». Блок «Секция магазина» имеет серверный
предпросмотр и выбор содержимого в панели редактора.

Каталог использует нативные `filter_*`, диапазон цены, сортировку и пагинацию
WooCommerce. На узких экранах фильтры свёрнуты. Карточка сохраняет нативную
галерею, таблицы, остатки, форму покупки и вариации: плашки синхронизируют
штатный select, цену и артикул. Без JS select доступен. «С этим покупают»
показывает связанные товары WooCommerce. Корзина/оформление используют
штатные блоки WooCommerce, включая бесплатный самовывоз и оплату при получении.
Поиск поддерживает названия и точные артикулы, включая артикул вариации.

Страницы: `/`, `/catalog/`, `/delivery/`, `/about/`, `/contacts/`,
`/privacy-policy/`, `/personal-data-consent/`, `/offer/`.
Контакты, юридические поля и карта берутся из «Данных магазина» при каждом
рендере. Ссылка карты должна иметь формат `https://yandex.ru/map-widget/...`
(или `yandex.com`); до заполнения отображается заглушка. Мессенджеры появляются
после заполнения данных магазина. Юридические тексты — предварительные,
финальные реквизиты и вычитка относятся к этапу 8.

Настройки воспроизводятся `scripts/setup-pages.sh` → `setup-pages.php`,
подключёнными к `setup.sh`. Отдельно, без повторной установки плагинов:

```sh
cd site
./bin/wp eval-file /scripts/setup-pages.php
```

Повторный запуск не создаёт дубли страниц/формы и сохраняет редакторские правки
текстов. Главная, страницы политики/оферты и адрес отправителя формы задаются
скриптом. В оформлении отдельные незаполненные заранее checkbox согласия ПДн
и принятия условий. ПДн проверяется API WooCommerce на сервере и сохраняется
с заказом. Contact Form 7 проверяет согласие и пишет обращения в Flamingo;
получатель письма динамически берётся из email магазина. Локально — Mailpit.
У формы отзыва также отдельный checkbox и серверная проверка.

Исходные SVG логотипов скопированы в тему, favicon — фирменный знак,
Apple touch — PNG 180×180, OG по умолчанию — PNG 1200×630. Изображения и шрифт
локальные. Товарные URL и импортированные сущности сохранены.

Проверки этапа 5: `npm test` (12 тестов), `npm run check:mcp`,
`site/scripts/verify.sh`, PHP lint и серверный preview в редакторе FSE.
Скриншоты 16 страниц при 375/768/1440 px — `site/data/screenshots/stage5/`.
Проверяются один H1, рабочие изображения, отсутствие горизонтального скролла,
фильтры/цена/сброс/сортировка/поиск, выбор вариации, обязательное согласие,
покупка → письмо и форма связи → письмо. Широкие таблицы прокручиваются внутри
секции. SEO-шаблоны, Метрика, WebP и целевые Lighthouse-оценки — этап 6.

API дополнительного checkout-поля:
[официальная документация WooCommerce](https://developer.woocommerce.com/docs/block-development/extensible-blocks/cart-and-checkout-blocks/additional-checkout-fields/).

## Этап 6: SEO и скорость

Настройки Rank Math воспроизводятся через `scripts/setup-seo.sh` →
`setup-seo.php` (подключены к `setup.sh`). Повторный импорт также применяет
SEO-настройки/alt и выполняет WebP-конвертацию. Оригиналы изображений сохранены;
Converter for Media отдаёт WebP по `Accept`, с исходным форматом как fallback.
906 файлов обработано, экономия около 110 МБ. Manrope — локальный woff2,
441 символ, кириллица/латиница, preload и `font-display: swap`.

Товары и категории получают шаблоны title/description, Open Graph и canonical.
Canonical пагинации указывает на саму страницу. Фильтры, сортировка, поиск,
корзина, оформление и аккаунт закрыты `noindex`; служебные страницы исключены
из sitemap. Rank Math: `/sitemap_index.xml` (также штатный `/sitemap.xml`).
В режиме запуска robots содержит исключения и Яндекс `Clean-param` по реальным
атрибутам (правила разбиты на строки короче 500 символов согласно
[ограничению Яндекса](https://yandex.ru/support/webmaster/ru/robot-workings/clean-param)).
При `blog_public=0`: `Disallow: /`, все страницы `noindex,nofollow`.
Этап 6 не открывает индексацию — это этап 8.

JSON-LD формирует Rank Math с дополнениями mu-plugin: единая Organization с
логотипом, Product/Offer или AggregateOffer, BreadcrumbList по видимым крошкам,
FAQPage с теми же вопросами и ответами, что на главной. Store (подтип
LocalBusiness) появляется после заполнения контактов; заглушки не выдаются за
реальный бизнес. Часы вида `Пн–Пт: 10:00–19:00` преобразуются в openingHours.
Бренд товара указывается только при наличии атрибута бренда/производителя.
Пустой бренд не заменяется именем магазина.

В «Данных магазина» вводятся номер Метрики и content-код Вебмастера.
Метрика подключается после разрешения аналитики, согласие можно изменить
кнопкой в подвале. Цели типа JavaScript-событие в кабинете Метрики:
`order`, `phone`, `messenger`, `form`. E-commerce: `detail`, `add`, `purchase`
в `dataLayer`; покупка доступна только по корректному ключу заказа и защищена
от повторной отправки при перезагрузке в том же браузере. Суммы/товары передаются
без имени, телефона и email покупателя. Пока номер не заполнен, счётчик и
баннер не загружаются. Реальные доступы/проверка получения данных — этап 8.
[Формат e-commerce Яндекса](https://yandex.ru/support/metrica/ru/ecommerce/data),
[цели reachGoal](https://yandex.ru/support/metrica/ru/general/goal-js-event),
[API фильтров Rank Math](https://rankmath.com/kb/filters-hooks-api-developer/).

Проверки этапа 6:

```sh
npm test
npm run check:mcp
site/scripts/verify.sh
node site/scripts/lighthouse-stage6.cjs
```

Lighthouse-скрипт **временно** включает `blog_public=1` для проверки режима
запуска и восстанавливает прежнее значение в `finally`; запускать на локальном
окружении, отдельно от E2E, которые также проверяют этот режим. Принудительное
завершение процесса может обойти `finally`: восстановление —
`cd site && ./bin/wp option update blog_public 0`.
Отчёты: `site/data/lighthouse/*-launch.json`.

Mobile Lighthouse: главная 100/100/100, категория 100/100/100, товар 97/100/100
(Performance / Accessibility / SEO). Это локальный аудит без активного внешнего
счётчика, не замер будущего VPS. Полный повтор нужен после переноса и подключения
реальной Метрики. При закрытой индексации SEO-балл ниже ожидаемо.


## Этап 7: VPS и перенос

Сайт перенесён на FirstByte Debian 12 (178.253.45.218), домен
https://soberi-stanok.ru/. Витрина открыта всем, nginx не запрашивает пароль.
Админка доступна по HTTPS в браузере, защищена паролем WordPress и ограничением
попыток входа. Данные администратора указаны владельцем.
Пароли вне Git: `site/data/server-access.txt` (600).

nginx + PHP 8.3-FPM + MariaDB + Redis работают без Docker. Публичные порты
только 22/80/443, SSH только по ключу, служебные базы и PHP — Unix-сокеты.
Индексация и отправка писем закрыты до этапа 8. Кэш исключает персональные
страницы/cookies/POST. Ежедневные локальные бэкапы на 14 дней; отдельного диска
нет, первая копия дополнительно скачана локально. Проверено изолированное
восстановление базы и файлов.

Скрипты установки, переноса, выкладки и подробные команды обслуживания:
[server/README.md](server/README.md).
